我认为你应该改变原来的识别策略：不要让 OCR 自动理解整个同花顺界面，而是让用户指定需要识别的区域，系统只识别指定区域内的内容。

对于你的 A 股智能看盘助手，这种方案更可靠，也更容易控制识别准确率。

我建议采用：

人工框选区域 + 区域模板配置 + 局部 OCR + 字体颜色分析 + 定时采集。

这比全屏 OCR 更适合同花顺 9.x。

这是提高准确率的关键。

例如：

```

    },
```

## 为什么这样更好？

因为 OCR 不再需要理解整个画面，只需要识别特定字段。

例如：

- 股票代码：只允许数字。
- 股票名称：中文、字母。
- 涨幅：数字、正负号、百分号。
- 最新价：数字、小数点。

还可以针对不同字段设置不同的 OCR 参数。

# 四、结合你的字体颜色规则

在区域化识别后，FontColorAnalyzer 就更容易实现。

我建议采用两种方式：

方式 A：整行颜色识别

适合股票名称、代码整体使用相同颜色的情况。

方式 B：股票名称单独采样

只分析股票名称的文字区域。

我更推荐方式 B。

例如：

| 股票名称颜色 | 识别结果  |
| ------ | ----- |
| 红色     | 三板及以上 |
| 橙色     | 一板    |
| 紫红色    | 二板    |
| 白色     | 自选股   |
| 黄色     | 非关注股票 |

而且颜色分析应该直接在原始截图上进行，不要先经过 OCR 图片预处理。

推荐处理流程：

```
区域截图
   |
   +--------------------+
   |                    |
   v                    v
RapidOCR          FontColorAnalyzer
   |                    |
   v                    |
股票名称坐标 -------------+
   |
   v
StockRowAssembler
   |
   v
StockClassifier
   |
   v
结构化股票数据
```

如果 OCR 识别出了股票名称，但是颜色区域识别失败，仍然保留股票数据，只将分类标记为未知。

# 五、区域坐标不要写死：采用相对坐标

同花顺窗口可能移动、改变大小，甚至用户更换显示器。

因此，不建议直接保存绝对屏幕坐标。

推荐保存两种坐标：

1. 同花顺窗口客户区坐标。
2. 相对于窗口客户区的归一化坐标。

例如：

```
struct CaptureRegion
{
    QString id;
    QString name;

    QRect relativeRect;

    double xRatio = 0.0;
    double yRatio = 0.0;
    double widthRatio = 0.0;
    double heightRatio = 0.0;

    int intervalMs = 1000;

    bool enabled = true;
};
```

计算实际坐标：

\\[ x=xRatio\times WindowWidth \\]

\\[ y=yRatio\times WindowHeight \\]

宽度和高度同理。

但是有一点需要注意：归一化坐标只适合窗口等比例变化。如果同花顺内部布局变化、列宽变化或分辨率/DPI 变化，还需要提供重新校准功能。

因此我建议同时保存：

- 原始窗口尺寸。
- 原始区域坐标。
- 归一化坐标。
- DPI 信息。
- 页面模板版本。

## 6.2 定时采集设计

建议每个区域由统一调度器管理，不要每个区域各自创建一个 OCR 线程。

```
struct RegionTask
{
    QString regionId;
    QImage image;
    QDateTime captureTime;
};
```

调度流程：

```
RegionScheduler
      |
      v
检查区域是否启用
      |
      v
检查任务是否正在执行
      |
      v
ScreenCapture
      |
      v
获取区域截图
      |
      v
图像变化检测
      |
      +---- 未变化 ---> 跳过 OCR
      |
      v
提交 OCR Worker
      |
      v
FontColorAnalyzer
      |
      v
StockRowAssembler
      |
      v
更新行情数据
```

这里建议加入一个很有价值的优化：

截图没有变化时，不重复执行 OCR。

可以使用图像哈希或区域差异检测。

但要注意，股票价格可能变化很小，不能只用粗粒度的感知哈希判断。建议采用分块差异检测，并为股票代码、名称等关键区域设置独立变化判断。

另外，采集和 OCR 必须解耦：某区域上一次任务尚未完成时，跳过新任务，避免 OCR 队列无限积压。

# 八、进一步优化：区域模板，而不只是区域坐标

这是我建议你采用的长期设计。

不同的同花顺页面，实际上对应不同的数据模板。

例如：

| 模板                    | 识别内容    | 业务用途   |
| --------------------- | ------- | ------ |
| StockRankingTemplate  | 涨幅榜、跌幅榜 | 市场排行   |
| WatchlistTemplate     | 自选股     | 自选股监控  |
| SectorRankingTemplate | 概念、行业排行 | 热点板块   |
| SectorStockTemplate   | 板块成分股   | 板块内部强度 |
| LimitUpTemplate       | 涨停列表    | 连板梯队   |

每个模板有自己的：

- 区域坐标。
- 表格列定义。
- OCR 识别规则。
- 字体颜色规则。
- 数据校验规则。
- 采集间隔。

这样以后增加页面，只需要增加模板，而不必修改底层采集引擎。

# 十、我建议你最终采用的方案

推荐架构

| 技术环节 | 方案                   |
| ---- | -------------------- |
| 界面定位 | Win32 窗口定位           |
| 区域配置 | 用户手动框选               |
| 坐标体系 | 窗口客户区相对坐标            |
| 截图   | Win32 GDI / Qt       |
| OCR  | RapidOcrOnnx         |
| 颜色识别 | HSV + RGB            |
| 表格识别 | 固定列区域 + 行定位          |
| 定时采集 | QTimer + 任务调度器       |
| 并发控制 | QThreadPool / 单任务不重入 |
| 配置存储 | JSON                 |
| 识别结果 | SQLite               |

最后有一个重要建议：第一版不要做自动识别页面布局。

你已经知道自己需要看哪些区域，也知道这些区域代表什么业务数据。让用户手动框选一次，保存配置，后续自动运行，工程实现简单得多，稳定性也更容易保证。

我建议第一版先完成一个独立的 `RegionCaptureDemo`，只实现三个功能：

1. 鼠标框选同花顺任意区域。
2. 设置 1 秒、2 秒、5 秒等采集间隔。
3. 实时显示区域截图、OCR 文字和字体颜色识别结果。

这三个功能验证通过后，再接入涨幅榜、自选股和热点板块分析引擎。
