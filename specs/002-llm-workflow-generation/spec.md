# Feature Specification: 大模型辅助创建自动化流程

**Feature Branch**: `[002-llm-workflow-generation]`

**Created**: 2026-10-31

**Status**: Draft

**Input**: User description: "根据项目当前已有 RPA 能力，对接大模型 API 与 Function Calling，将自然语言任务拆解为 WinAuto 支持的标准流程定义；优先生成并校验标准流程 JSON，不直接生成或执行任意脚本。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从自然语言生成流程草稿 (Priority: P1)

用户用自然语言描述要完成的桌面自动化任务，选择已配置的大模型服务并提交请求。系统将任务拆解成可执行步骤，生成符合 WinAuto 现有流程格式的草稿，并将草稿载入流程编辑器供用户查看。

**Why this priority**: 将自然语言任务转为现有引擎可理解的流程，是本功能的核心价值；无需先自动执行，就能独立验证规划和流程生成是否可用。

**Independent Test**: 提交一个仅使用当前支持操作的任务，例如启动程序、激活窗口、点击控件、输入文本和等待；确认得到结构完整的流程草稿，且草稿中的步骤与用户意图对应。

**Acceptance Scenarios**:

1. **Given** 用户已配置可用的大模型服务并输入清楚的桌面任务，**When** 用户发起生成，**Then** 系统返回一个可在 WinAuto 中编辑的流程草稿，并保留用户原有工作流不变。
2. **Given** 任务能够拆解为多个已有操作，**When** 系统生成草稿，**Then** 步骤顺序、目标窗口、操作参数及必要的等待/条件与任务描述相符。
3. **Given** 用户的任务描述不完整且缺少生成安全流程所必需的信息，**When** 系统无法可靠推断，**Then** 系统指出缺少的信息并请求用户补充，而不是静默生成猜测性的目标或操作。

---

### User Story 2 - 检查、修正并保存生成的流程 (Priority: P1)

用户在编辑器中检查模型生成的流程，查看字段或语义校验问题，手动修正不符合要求的内容后保存。用户可以按现有流程运行和确认机制运行已审核的流程。

**Why this priority**: 模型输出可能无效或不适合实际环境；在执行前由现有流程校验和用户审核把关，才能安全复用当前 RPA 引擎。

**Independent Test**: 提交会导致无效流程的任务或使用无效模型响应，确认不合格草稿不能被误认为可运行；再修正草稿、保存并验证可重新打开。

**Acceptance Scenarios**:

1. **Given** 模型返回的草稿缺少必需字段、引用未定义窗口或使用不支持的步骤，**When** 系统校验草稿，**Then** 用户看到对应步骤和字段的问题，且该草稿不能直接启动运行。
2. **Given** 草稿通过现有流程校验，**When** 用户选择载入或保存，**Then** 系统保留流程编辑器已有的校验、未保存修改保护及保存行为。
3. **Given** 用户准备执行包含敏感或高风险操作的生成流程，**When** 用户启动运行，**Then** 仍须遵循现有运行前摘要、风险确认和停止机制；生成成功不代表授权执行。

---

### User Story 3 - 管理模型连接并了解能力边界 (Priority: P2)

用户配置模型服务、模型名称和访问凭据，并在生成前了解当前版本可规划的自动化能力。连接失败、模型不可用或请求失败时，用户可以看到可理解的错误并保留已有流程。

**Why this priority**: 稳定且可管理的模型连接是持续生成流程的前提；明确能力边界可避免用户误以为系统能够完成当前引擎尚不支持的数据处理或定时任务。

**Independent Test**: 分别使用有效配置、缺少凭据、无效凭据及不可达服务尝试连接或生成，确认状态和错误清晰，且不会丢失已有编辑内容或泄露凭据。

**Acceptance Scenarios**:

1. **Given** 用户尚未完成模型服务配置，**When** 用户尝试生成流程，**Then** 系统说明需配置的信息，不发送无效请求。
2. **Given** 模型服务拒绝请求、超时或返回无法识别的结果，**When** 生成失败，**Then** 系统说明失败原因，保留用户输入及当前工作流，且不载入部分或伪装成功的草稿。
3. **Given** 用户提出当前版本不支持的能力（例如 Excel 文件读写或按计划定时触发），**When** 系统评估该请求，**Then** 系统明确标示超出当前能力，并且不将其伪造为已实现的流程步骤。
4. **Given** 用户更换模型服务配置或清除凭据，**When** 配置保存完成，**Then** 后续生成使用新配置，界面和日志不显示完整访问凭据。

### Edge Cases

- 模型返回格式错误、缺少步骤、包含未知字段、超出响应大小限制或未按要求调用可用工具时，系统不得将其作为有效流程载入。
- 任务混合了支持和不支持的能力时，系统应指出不可完成部分；只有在用户明确接受缩减范围后才生成覆盖可支持部分的草稿。
- 模型给出不存在的窗口、无法唯一定位的控件或不安全的输入内容时，系统应要求用户补充或修改，不得擅自选择目标。
- 请求过程中网络中断、服务限流、鉴权失败或用户取消时，保留已编辑流程和任务文本，并给出可区分的状态。
- 用户编辑器已有未保存修改时，生成、载入或放弃草稿的操作不得静默覆盖这些修改。
- 模型返回任意 Python、Lua、JavaScript 或其他可执行源代码时，不得自动写入脚本步骤或执行；本功能生成标准流程步骤，不以任意代码作为替代输出。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户用自然语言描述目标任务，并从流程编辑器发起流程生成。
- **FR-002**: 系统 MUST 允许用户配置至少一种大模型服务、模型名称及访问凭据，并在生成前识别缺失或无效的必需配置。
- **FR-003**: 系统 MUST 支持通过结构化工具调用让模型表达规划意图；模型只能使用当前版本明确提供的能力，不能以工具调用绕过 WinAuto 的流程校验和执行授权。
- **FR-004**: 系统 MUST 将生成结果转换为 WinAuto 当前工作流格式，而不是引入与现有引擎不兼容的独立 action/trigger 格式。
- **FR-005**: 系统 MUST 至少允许模型规划现有引擎支持的窗口绑定或启动、激活窗口、控件操作、文本输入、按键、等待及流程控制步骤；每种生成步骤 MUST 满足现有字段和语义规则。
- **FR-006**: 系统 MUST 在呈现草稿前使用现有工作流校验规则检查生成结果，并将结构或语义错误定位到对应步骤或字段。
- **FR-007**: 系统 MUST 将有效结果作为编辑器中的草稿供用户检查和修改，不得自动覆盖其他工作流或自动开始执行。
- **FR-008**: 系统 MUST 保持现有工作流内容、用户未保存修改和任务输入，直到用户明确接受或放弃生成草稿。
- **FR-009**: 用户确认运行草稿时，系统 MUST 使用现有运行前摘要、风险确认、权限检查、停止控制及执行结果报告；模型调用或草稿生成不得视为运行授权。
- **FR-010**: 系统 MUST 拒绝或要求重新生成包含未知步骤类型、无效窗口引用、缺失必需参数或违反现有流程约束的结果。
- **FR-011**: 系统 MUST 明确告知用户当前版本不可规划或执行的请求，不得把缺失的能力描述成已成功生成。第一阶段不包含 Excel 文件读写、数据导出专用操作或定时触发。
- **FR-012**: 系统 MUST 为服务不可达、鉴权失败、限流、超时、取消及无效模型响应提供清晰且可区分的反馈，并保留用户现有工作。
- **FR-013**: 系统 MUST 避免在界面提示、运行日志和错误报告中显示完整访问凭据；用户可更新或清除已保存的模型配置。
- **FR-014**: 系统 MUST 不得自动生成、导入或执行任意 Python、Lua、JavaScript 或其他通用代码作为实现用户任务的默认路径。
- **FR-015**: 系统 MUST 在任务无法可靠映射到现有能力、或目标窗口/控件有歧义时，请求用户补充信息或明确缩减任务范围。
- **FR-016**: 系统 MUST 在用户取消模型请求或生成过程失败时，不载入不完整草稿，并保留已存在的流程编辑状态。

### Key Entities *(include if data involved)*

- **模型连接配置**：描述服务来源、模型名称和访问凭据；凭据由用户管理，并在显示和诊断中受到保护。
- **生成请求**：用户提交的任务文本及生成时选定的模型配置。
- **能力目录**：当前版本允许模型规划的 WinAuto 操作范围及各操作所需信息。
- **流程草稿**：模型返回并转换为 WinAuto 标准格式、尚待用户检查和接受的流程。
- **校验结果**：针对草稿中步骤和字段的有效性结论及可定位的问题。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对于能由现有操作表达的标准桌面任务，用户可在一次生成请求后获得可检查的流程草稿；至少 90% 的验收样例在不超过一次修正后通过现有工作流校验。
- **SC-002**: 所有被接受的草稿均通过现有工作流校验；无效或不完整的模型响应载入为可运行流程的数量为零。
- **SC-003**: 100% 的验收场景中，生成流程不会在用户明确审核并启动运行前操作目标应用。
- **SC-004**: 对不支持的 Excel 读写和定时触发请求，系统在生成流程前明确提示边界的比例为 100%，且不会生成对应的伪造步骤。
- **SC-005**: 模型配置、取消、网络错误及无效响应场景下，用户已有编辑内容丢失次数为零。
- **SC-006**: 在凭据查看、请求失败和日志检查验收中，完整访问凭据暴露次数为零。

## Assumptions

- 第一阶段面向 WinAuto 桌面流程的创建者；用户负责检查目标窗口、控件定位和任务结果。
- 模型服务通过用户配置的在线 API 使用；用户负责提供有效凭据并接受相应网络访问。
- 第一阶段以模型生成 WinAuto 标准流程草稿为交付，不建设后台计划任务系统，也不直接执行模型逐次发出的实时桌面操作。
- 可规划的工具范围以当前项目已实现并可由工作流表达的操作为准。现有脚本步骤虽可由用户显式编辑和确认，仍不作为模型生成任务的任意代码后门。
- 示例中的 Excel 读写、销售数据导出和“每天上午 9 点”调度依赖尚未实现的能力，列为后续独立功能，不纳入此阶段验收。
- 初始模型服务范围包含 Claude 服务和 GPT 系列服务；具体可用模型取决于用户配置和服务商可用性。
- 生成草稿进入现有编辑器，不修改工作流格式版本；现有语义校验、运行权限和用户确认流程继续作为权威规则。
