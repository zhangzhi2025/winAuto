# Feature Specification: Agent WebSocket 对接

**Feature Branch**: `[003-agent-websocket-integration]`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "新增一个agent对接，之前大模型保留，按server/server.py方式对接，需要配置ws地址，sessionid,项目目录等"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置并连接 Agent 服务 (Priority: P1)

用户在 WinAuto 中配置 Agent 服务的 WebSocket 地址、项目工作目录和可选的 session ID，然后发起连接。用户可以选择创建新会话，或通过已有 session ID 恢复会话；新会话返回的 session ID 会展示给用户，便于后续恢复。

**Why this priority**: 正确连接 Agent 并将其限定到用户指定的项目目录，是使用 Agent 的前提。

**Independent Test**: 配置有效的 WebSocket 服务和有效项目目录，分别创建新会话和恢复已有会话；确认连接状态、工作目录和 session ID 均可见。再以无效地址、目录或 session ID 连接，确认得到明确错误且不会清除已有配置。

**Acceptance Scenarios**:

1. **Given** 用户已填写可用的 WebSocket 地址和有效项目目录且未填写 session ID，**When** 用户连接并开始新会话，**Then** 系统连接到服务、将指定项目目录作为会话工作目录，并显示服务返回的 session ID。
2. **Given** 用户已填写有效的 WebSocket 地址、项目目录和已有 session ID，**When** 用户选择恢复会话，**Then** 系统尝试恢复该会话并显示连接结果及当前 session ID。
3. **Given** 地址格式错误、服务不可达、项目目录无效或 session ID 无法恢复，**When** 用户尝试连接，**Then** 系统说明失败原因，保留用户填写的配置和当前工作流。
4. **Given** 用户已经配置大模型服务，**When** 用户进入 Agent 配置或会话入口，**Then** 原有大模型配置及流程生成功能仍可使用，Agent 配置不会覆盖它们。

### User Story 2 - 与 Agent 进行会话交互 (Priority: P1)

用户连接或恢复会话后，可以向 Agent 发送任务文本，并查看 Agent 的持续回复、工具活动和每轮处理状态。用户可以中止正在处理的请求，或断开会话。

**Why this priority**: Agent 会话是此对接的核心用途；用户需要知道请求是否仍在处理，并能控制会话生命周期。

**Independent Test**: 连接测试服务并发送一条请求，确认回复和处理状态能够显示；在处理期间中止请求，确认界面停止等待且后续请求可继续；断开后确认会话入口回到未连接状态。

**Acceptance Scenarios**:

1. **Given** Agent 会话已连接且没有正在处理的请求，**When** 用户发送非空任务文本，**Then** 系统将请求发送到当前会话，并显示 Agent 的增量回复及本轮开始和结束状态。
2. **Given** Agent 正在处理一条请求，**When** 用户再次发送请求，**Then** 系统明确告知当前请求尚未完成，不会并发提交第二条请求。
3. **Given** Agent 正在处理请求，**When** 用户选择中止，**Then** 系统请求 Agent 停止当前处理并展示已中止状态；会话仍可继续使用，除非用户另行断开。
4. **Given** 用户断开 Agent 会话或连接意外中断，**When** 用户查看会话入口，**Then** 系统显示断开状态，并且不会把断开误报为请求成功。
5. **Given** Agent 返回可识别的工具活动或错误，**When** 系统展示该事件，**Then** 用户可以区分 Agent 回复、工具活动、请求完成和请求失败。

### User Story 3 - 管理连接设置并保护现有工作 (Priority: P2)

用户可以查看、修改和保存 Agent 对接设置，在会话前确认服务地址和项目目录；连接、恢复或请求失败时，原有流程及未保存编辑内容保持不变。

**Why this priority**: 连接参数通常需要在多个会话间复用，且 Agent 的网络和文件操作不能意外影响用户当前编辑的工作流。

**Independent Test**: 保存并重新打开 Agent 设置，确认地址、工作目录和 session ID 按预期保留；制造连接错误和请求错误，确认流程内容及未保存修改保持不变，并确认敏感信息不进入日志。

**Acceptance Scenarios**:

1. **Given** 用户修改了 Agent 设置，**When** 用户保存并重新打开设置，**Then** 系统展示已保存的非敏感连接参数；用户可以更新或清除这些参数。
2. **Given** 用户当前工作流有未保存修改，**When** 用户连接 Agent、恢复会话或发送请求，**Then** 系统不覆盖或丢弃该工作流及其未保存修改。
3. **Given** Agent 连接或请求失败，**When** 用户重试或修改配置，**Then** 系统保留任务输入和可恢复的会话配置，并给出明确的失败状态。
4. **Given** Agent 将对项目文件或桌面环境执行有副作用的工具操作，**When** 该操作需要用户授权，**Then** 系统遵循 Agent 服务提供的权限确认机制；WinAuto 不得因连接成功而静默扩大授权或自动批准所有操作。

### Edge Cases

- WebSocket 地址为空、格式不正确，或使用不支持的连接协议时，连接不得开始，并应指出需要修正的设置。
- 服务在握手后断开、响应超时、返回错误事件或发送无法识别的消息时，系统应区分连接状态和请求结果，不得伪报成功。
- 项目目录不存在、不是目录或无法访问时，系统应在开始会话前提示用户修正。
- session ID 为空时应允许创建新会话；session ID 无效或过期时，应提示恢复失败，并允许用户改为创建新会话。
- Agent 回复为空、请求文本为空或另一条请求仍在进行时，系统不得发送无效或重复请求。
- 用户关闭会话窗口或应用时，正在进行的请求应被安全中止或断开；不得遗留显示为仍在运行的会话状态。
- 服务发送大量回复或持续工具事件时，系统应继续保持界面可用，并明确显示当前处理状态。
- 切换到 Agent 会话或保存 Agent 设置不得更改现有大模型服务、既有流程生成结果或编辑器内容。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在现有大模型流程生成功能之外提供独立的 Agent 对接入口；用户可以分别配置和使用两者。
- **FR-002**: 系统 MUST 允许用户配置并保存 Agent WebSocket 地址、项目工作目录和 session ID；session ID MUST 可留空以创建新会话。
- **FR-003**: 系统 MUST 在连接前检查必需设置；WebSocket 地址或项目目录无效时，MUST 提示用户并阻止开始会话。
- **FR-004**: 系统 MUST 支持创建 Agent 新会话，以及使用用户提供的 session ID 恢复已有会话。
- **FR-005**: 系统 MUST 将用户指定的项目目录作为 Agent 会话的工作目录，并在连接成功后向用户显示实际使用的目录。
- **FR-006**: 系统 MUST 展示 Agent 服务返回的新 session ID，并允许用户查看、复制、更新或清除用于后续恢复的 session ID。
- **FR-007**: 系统 MUST 允许用户在已连接会话中提交非空请求、接收 Agent 回复和处理状态，并在当前请求未完成时阻止并发提交。
- **FR-008**: 系统 MUST 允许用户中止当前请求和断开会话，并准确显示处理中止、已中止、已断开及连接失败等状态。
- **FR-009**: 系统 MUST 将 Agent 回复、工具活动、请求完成和错误作为可区分的事件呈现；未知或格式错误的服务消息不得被当作成功回复。
- **FR-010**: 系统 MUST 对连接失败、会话恢复失败、网络中断和请求失败提供明确反馈，并保留可重试的设置及用户输入。
- **FR-011**: Agent 连接、会话恢复、请求发送或断开 MUST NOT 覆盖当前工作流、清除未保存修改或替换大模型生成的流程草稿。
- **FR-012**: 系统 MUST 保持现有大模型服务配置和流程生成功能可用；Agent 设置的保存、修改或清除 MUST NOT 改变大模型设置。
- **FR-013**: 系统 MUST 显示 Agent 操作可能触及的工作目录，并在会话开始前使用户能够检查该目录。
- **FR-014**: 系统 MUST NOT 将 Agent 连接或会话创建视为对所有工具、文件或桌面操作的授权；需要授权的副作用操作 MUST 遵循服务提供的权限确认机制，不得由 WinAuto 静默自动批准。
- **FR-015**: 系统 MUST 在诊断信息和日志中避免记录完整任务内容以外的敏感凭据；连接地址中的凭据或令牌（如存在）不得被完整显示或记录。
- **FR-016**: 系统 MUST 在用户断开或连接意外终止后清理活动会话状态；重新连接前不得把过期连接呈现为可用状态。

### Key Entities *(include if data involved)*

- **Agent 连接配置**：Agent 服务地址、项目工作目录及用户选择保存的 session ID。
- **Agent 会话**：与 Agent 服务关联的活动会话，包括连接状态、当前工作目录和服务分配的 session ID。
- **Agent 请求轮次**：用户提交的一条请求及对应的流式回复、工具活动、完成、中止或失败状态。
- **Agent 服务事件**：由服务发送的回复片段、工具活动、状态通知或错误信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户仅配置 WebSocket 地址和项目目录即可成功创建新 Agent 会话；session ID 由服务返回并可见。
- **SC-002**: 用户可通过已保存的 session ID 恢复会话；验收中有效和无效 session ID 的结果均可明确区分。
- **SC-003**: 对有效请求，用户能够看到回复内容及请求状态；对失败、中止和断开场景，成功状态误报次数为零。
- **SC-004**: Agent 对接的配置或运行流程导致已有工作流及未保存修改丢失的验收次数为零。
- **SC-005**: 添加 Agent 对接后，原有大模型配置和流程生成验收场景仍全部可完成，且 Agent 设置不改变大模型配置。
- **SC-006**: 需要用户授权的 Agent 副作用操作中，未经授权而由 WinAuto 自动批准的验收次数为零。

## Assumptions

- Agent 服务由用户另行部署或提供，并以 WebSocket 暴露兼容的会话服务；WinAuto 不负责安装、托管或认证该服务。
- 新建会话由服务分配 session ID；用户提供 session ID 时表示尝试恢复该会话。
- 用户通过配置的项目目录明确指定 Agent 的工作范围；WinAuto 显示该目录，但 Agent 服务本身的文件和工具边界仍由服务端权限策略决定。
- 第一阶段包含连接配置、会话新建/恢复、文本交互、状态和工具事件展示、中止及断开；不包含替换现有大模型流程生成、自动生成工作流或自动执行本地 Agent 服务。
- Agent 服务应提供连接生命周期和请求状态所需的响应；对未知消息类型，客户端以不成功或未知状态处理，不推断执行成功。
- Agent 设置与现有大模型设置分离保存；session ID 由用户决定是否持久保存。
