# Feature Specification: RPA OCR Integration

**Feature Branch**: `[004-ocr-integration]`

**Created**: 2026-11-11

**Status**: Draft

**Input**: User description: "RPA需要跟ocr对接，增加ocr功能，目前跟RapidOcrOnnx对接，RapidOcrOnnx在代码已在@third_party目录下。"

## User Scenarios & Testing

### User Story 1 - Use recognized text as a workflow target (Priority: P1)

流程作者希望在目标应用界面文字稳定、但 UI Automation 或图像模板不适用时，通过屏幕上的文字定位控件区域，并复用现有点击、等待和断言步骤。

**Why this priority**: OCR 的主要价值是把可见文本转换成可用于 RPA 定位的屏幕区域，能直接补足现有定位策略。

**Independent Test**: 用一张已知界面截图和配置好的 OCR 模型识别指定文字；验证返回文字及屏幕坐标，再在本地测试窗口中用 OCR 定位执行等待/断言和受安全检查保护的点击。测试 0 个、多于 1 个候选、关键词过滤、八方向筛选和 fallback 场景。

**Acceptance Scenarios**:

1. **Given** 流程步骤使用 OCR 定位器，且目标窗口中仅有一个匹配文本，**When** 引擎定位该目标，**Then** 返回该文本框的屏幕物理像素区域，既有步骤可按该位置继续工作。
2. **Given** OCR 文本在目标窗口中不存在，**When** 执行定位，**Then** 返回未找到；若它位于 fallback 链中，仅按现有规则在 `ElementNotFound` 时尝试下一项。
3. **Given** OCR 找到多个匹配文本且未设置明确的首项策略，**When** 执行定位，**Then** 报告歧义并拒绝猜测或点击。
4. **Given** OCR 定位框被遮挡或其坐标不属于目标窗口，**When** 步骤尝试点击，**Then** 沿用现有输入安全检查并拒绝不安全点击。
5. **Given** 关键词过滤后仍有多个候选，**When** 流程定位器指定一个八方位方向，**Then** 只保留位于目标窗口中心相应方向的候选；仍有多个候选时继续报告歧义。

### User Story 2 - Configure and verify the OCR engine (Priority: P1)

用户可以配置 RapidOcrOnnx 所需的检测、方向分类、识别 ONNX 模型和字符字典，查看配置状态，并用截图验证模型能否正常加载和识别。

**Why this priority**: OCR 定位只有在模型和运行库有效时才能使用；明确配置和可诊断的就绪状态可以避免流程运行时才发现缺失依赖。

**Independent Test**: 分别配置有效模型文件、缺失文件和不兼容文件；验证成功初始化、明确诊断和可重试行为。使用固定测试图片执行识别并检查文本与文本框。

**Acceptance Scenarios**:

1. **Given** 用户已提供有效的四个模型/字典文件，**When** 保存并测试 OCR 配置，**Then** 系统报告可用并返回测试图中的文本及位置。
2. **Given** 模型文件缺失、不可读或无法初始化，**When** 用户测试配置或流程请求 OCR，**Then** 系统报告具体配置问题，不得把识别失败伪装成“未找到文本”。
3. **Given** 默认模型文件缺失、路径被用户更改为无效位置或本机原生依赖不可用，**When** 查看 OCR 状态，**Then** 系统指出未就绪的具体模型类别或依赖，并提供可修正的配置诊断。

### User Story 3 - Call OCR from Python and Lua scripts (Priority: P1)

流程作者希望在 Python 或 Lua 脚本步骤中请求 OCR，获取目标窗口或指定区域中的识别文本和位置，并在脚本后续逻辑中使用；OCR 仍通过现有脚本宿主代理执行，不向脚本暴露本地窗口句柄或绕过引擎安全边界。

**Why this priority**: 脚本步骤已支持自定义决策和受控宿主操作。OCR 脚本接口能让用户组合文字识别与已有脚本能力，而无需把每一种动态逻辑固化为新的流程步骤。

**Independent Test**: 分别从 Python 和 Lua 脚本请求同一测试窗口的 OCR 结果，验证返回结构包含识别文字及位置；再验证无效窗口、无效参数、宿主错误、取消和脚本超时均得到明确失败，且原有脚本权限与前台/遮挡检查不被绕过。

**Acceptance Scenarios**:

1. **Given** 脚本步骤在有效工作流窗口上调用 OCR，**When** OCR 宿主完成识别，**Then** Python 和 Lua 均收到同一定义的文本候选列表及坐标。
2. **Given** 脚本传入可选关键词，**When** OCR 识别出多个文字区域，**Then** 宿主只返回识别文本以该关键词开头的区域及其完整文字和位置；不传关键词时返回全部符合其他条件的区域。
3. **Given** 脚本调用 OCR 时发生配置错误、捕获失败、超时或取消，**When** 宿主返回结果，**Then** 脚本收到明确错误，不得把失败伪装成空识别结果。
4. **Given** 脚本请求 OCR，**When** 宿主处理请求，**Then** OCR 遵循脚本步骤既有的截止时间、取消和请求大小限制，不向脚本暴露原生句柄或提供未授权桌面输入能力。

### User Story 4 - Inspect OCR results and preserve workflow safety (Priority: P2)

用户可针对指定目标窗口检查 OCR 识别结果，理解匹配文字和候选位置；OCR 服务失败或发生歧义时，当前流程及未保存编辑不会丢失，也不会把识别到的内容静默写入工作流或日志。

**Why this priority**: 文字识别会受缩放、遮挡和画面变化影响；检查结果有助于诊断，但不能削弱现有 RPA 的保守定位和输入安全边界。

**Independent Test**: 对测试窗口检查 OCR 结果，覆盖无文字、重复文字、低置信度、超时/取消及无效图像；确认当前流程不被更改，并检查日志不含完整识别文本。

**Acceptance Scenarios**:

1. **Given** 用户选择目标窗口并请求 OCR 检查，**When** 检查完成，**Then** 系统显示识别文本、候选框和置信度，且不执行任何桌面输入。
2. **Given** OCR 推理正在执行，**When** 用户取消或关闭检查界面，**Then** 系统停止等待并返回明确取消状态，编辑器保持响应。
3. **Given** OCR 操作失败或返回歧义，**When** 用户修改模型/定位配置后重试，**Then** 原工作流及未保存修改保持不变。
4. **Given** OCR 读取到用户界面文字，**When** 产生诊断或日志，**Then** 默认不记录完整识别文本或截图内容。

## Edge Cases

- ONNX Runtime、OpenCV、ONNX 模型或字典缺失、版本/架构不兼容、文件无读取权限或路径失效。
- 输入截图为空、尺寸过大、目标窗口最小化，或截图不能代表目标窗口当前可见内容。
- OCR 没有检测到文字、文本置信度不足、同一文字重复出现或不同文本框彼此重叠。
- 文本包含中文、拉丁字符、空格、标点或多行内容；流程中的匹配文本不得因编码转换被损坏。
- 多显示器、DPI 缩放或窗口移动/调整大小导致 OCR 图像坐标与屏幕物理像素坐标换算错误。
- 推理耗时较长、连续步骤重复初始化模型、用户取消或应用关闭时仍有识别任务运行。
- 用户只配置了部分模型文件或更改模型目录后运行已有流程。
- OCR 作为 fallback 成员时发生初始化错误或推理错误；这类错误不得被误认为文本不存在而静默继续。
- 关键词未匹配任何 OCR 文本区域，或多个区域均以关键词开头；匹配时只过滤保留符合条件的区域，不因多条匹配而丢弃其他符合条件的结果。
- 指定方向后没有候选落在该方向、候选中心与目标窗口中心重合、候选刚好位于方向扇区边界，或同一方向仍有多个候选。
- Python/Lua 脚本在 OCR 请求等待期间取消、超时，或反复发起超出宿主限制的 OCR 请求。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 使用 `third_party/RapidOcrOnnx` 中的 RapidOcrOnnx 能力提供本地 OCR；OCR 图像识别不得依赖外部网络服务。
- **FR-002**: 系统 MUST 支持使用并验证 RapidOcrOnnx 所需的检测模型、方向分类模型、识别模型及字符字典；当前仓库已提供 `ch_PP-OCRv3_det_infer.onnx`、`ch_ppocr_mobile_v2.0_cls_train.onnx`、`ch_PP-OCRv3_rec_infer.onnx`、`en_PP-OCRv3_rec_infer.onnx` 和 `ppocr_keys_v1.txt`。用户仍可配置模型路径；未配置或初始化失败时须明确报告 OCR 尚未就绪。
- **FR-003**: 系统 MUST 在流程定位器中提供 OCR 文本定位能力，允许作者指定要查找的文字、匹配方式、可选搜索范围和最低识别置信度。
- **FR-004**: 系统 MUST 使用目标窗口的图像进行 OCR，并把识别文本框映射为屏幕物理像素坐标；不得将 OCR 匹配到的坐标直接视为输入授权。
- **FR-005**: OCR 定位 MUST 可用于所有接受既有 locator 的目标定位场景，包括支持定位器的动作、等待、断言、后置校验和条件判断；具体遵循既有步骤语义。
- **FR-006**: OCR 定位 MUST 支持无匹配、唯一匹配及多个匹配的明确结果；关键词和方向筛选后默认仍有多个候选时失败，只有流程显式选择 `ambiguity: first` 时才可选择一个候选。
- **FR-007**: OCR 定位器 MUST 可作为现有 fallback 策略的成员；fallback 仅在 OCR 明确返回 `ElementNotFound` 时继续，模型初始化、图像处理或推理错误 MUST 明确失败。
- **FR-008**: 系统 MUST 在执行基于 OCR 的点击或其他输入前继续执行现有窗口有效性、前台/遮挡及落点检查；OCR 不得绕过输入安全策略。
- **FR-009**: 用户 MUST 能对目标窗口执行只读 OCR 检查，并查看识别文本、匹配框和置信度；该检查不得执行桌面动作或修改工作流。
- **FR-010**: 系统 MUST 以明确错误区分 OCR 配置无效、依赖不可用、图像捕获失败、推理失败、取消、无匹配和候选歧义。
- **FR-011**: OCR 初始化和推理 MUST 不阻塞编辑器主线程；用户取消或关闭相关操作时系统 MUST 结束等待并清理活动任务状态。
- **FR-012**: 系统 MUST 在工作流 JSON 读写、语义校验、schema、编辑器和执行器中一致支持 OCR 定位器；无效字段和无效范围必须在执行前给出带路径诊断。
- **FR-013**: OCR 设置 MUST 与工作流 JSON 和现有大模型/Agent 配置分离；模型文件路径等必要设置可持久化，但识别结果和截图不得未经用户操作持久化。
- **FR-014**: 系统 MUST 默认避免在日志和持久化诊断中记录完整 OCR 识别文本或截图内容；只提供识别错误所必需的脱敏信息。
- **FR-015**: OCR 不能用作身份验证、权限授予或授权操作的唯一依据；其定位结果与现有视觉定位一样，仍须通过原有风险确认和输入安全检查。
- **FR-016**: Python 和 Lua 脚本 MUST 能通过现有受控脚本宿主请求 OCR，并取得结构化识别文本和文本框位置；两种语言使用一致的能力和结果语义。
- **FR-017**: 脚本 OCR 请求 MUST 绑定到脚本可用的工作流窗口别名及其当前图像，遵循脚本步骤既有的取消、超时、请求大小限制和宿主策略；不得向脚本暴露原生窗口句柄或绕过权限检查。
- **FR-018**: OCR MUST 对识别出的文字区域提供可选关键词过滤；指定关键词时，只保留识别文本以该关键词开头的区域，并返回这些区域的完整识别文本及位置；未指定关键词时保留所有符合其余条件的区域。
- **FR-019**: 关键词过滤 MUST 在所有识别出的文字区域上逐个执行；多个区域以关键词开头时 MUST 返回全部匹配区域，而不是猜测或只选其中一个。没有匹配区域时返回明确的空结果/未找到；工作流定位器若需唯一目标，继续按现有歧义策略处理多个候选。
- **FR-020**: 工作流 OCR 定位器 MUST 支持可选八方位方向过滤（左、左前、前、右前、右、右后、后、左后）。方向按候选文本框中心相对于目标窗口客户区中心判定；方向筛选在关键词过滤后执行，只保留指定方向扇区内的候选。方向不能唯一确定目标时，MUST 沿用现有歧义处理，不得隐式取最近项。

### Key Entities

- **OCR 配置**：RapidOcrOnnx 模型/字典文件路径、推理线程设置及配置就绪状态。
- **OCR 定位器**：要匹配的目标文本、匹配方式、置信度阈值、可选目标窗口搜索区域和多候选策略。
- **OCR 方向过滤**：可选八方位值，按 OCR 文本框中心相对目标窗口客户区中心所在的方向扇区筛选候选；扇区边界按顺时针方向归入边界之后的扇区。
- **OCR 文本候选**：一次图像识别得到的文本内容、文本框、识别/检测置信度和屏幕坐标；仅作为当前识别的运行期结果。
- **OCR 检查结果**：用户只读检查的识别候选及状态，不自动写入工作流或作为桌面动作。
- **关键词过滤**：对一次 OCR 识别得到的文字区域按识别文本前缀筛选；返回匹配区域自身的完整文本、文本框及置信度，不额外推导或裁剪二次识别区域。
- **脚本 OCR 请求**：Python/Lua 通过受控宿主提交的 OCR 操作，包含工作流窗口别名和可选关键词过滤参数，并接收结构化候选或明确错误。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在已配置有效 RapidOcrOnnx 模型的环境中，用户可通过 OCR 定位器匹配测试窗口中的唯一目标文本，并获得落在目标文本框内的屏幕物理像素坐标。
- **SC-002**: 固定测试图片集中的每张图片都能通过测试接口返回识别文本和对应文本框；无效模型/依赖、无匹配和多匹配均与成功结果明确区分。
- **SC-003**: 对包含 0、1 和多个匹配项的 OCR 工作流测试，系统分别产生未找到、唯一定位和歧义结果；未显式允许时不自动选择多个候选中的一个。
- **SC-004**: OCR 配置错误、捕获失败、推理错误、取消及 fallback 测试中，错误结果误报为成功或未找到的次数为零。
- **SC-005**: OCR 检查和推理期间编辑器保持响应；取消操作后不会遗留显示为运行中的 OCR 会话。
- **SC-006**: OCR 功能的配置与执行不会更改现有工作流未保存内容、模型/Agent 设置或执行授权状态。
- **SC-007**: Python 和 Lua 脚本对相同 OCR 请求返回结构一致；脚本超时、取消或宿主失败均不会被表示为成功的空结果。
- **SC-008**: 给定包含多条 OCR 文字区域的图像，指定关键词后只返回所有识别文本以该关键词开头的区域及其完整文本；未指定关键词时返回全部合格区域；无匹配返回空候选/未找到。
- **SC-009**: 对关键词过滤后分布于八个方向的候选，指定任一方向仅保留该方向候选；定位器未指定方向或指定方向内仍有多个候选时，默认报告歧义，只有显式设置 `ambiguity: first` 才按既定顺序选择，绝不静默选择最近候选。

## Assumptions

- 本功能首期面向现有 Windows 桌面 RPA；OCR 结果以目标窗口图像为依据，并复用当前窗口物理坐标和输入安全规则。
- `third_party/RapidOcrOnnx` 提供源码和依赖集成入口；`models` 目录已包含检测、方向分类、中文/英文识别 ONNX 模型和字符字典。运行前仍需确认 ONNX Runtime、OpenCV 的构建和运行依赖可用。
- 首期使用 RapidOcrOnnx 当前 CPU 推理路径；GPU/CUDA 配置及运行时切换不在本规格范围内。
- OCR 识别可能受模型、DPI、字体、语言和遮挡影响；匹配需基于结果明确失败，不保证所有 UI 文本均可识别。
- OCR 能力补充现有 UIA、坐标和图像定位；不替换现有定位器或自动修改已有流程。
- 字符匹配至少需要精确匹配和包含匹配；文本比较与空白处理规则由实现设计确定，并在流程格式中保持稳定、可测试。
- Python/Lua 使用既有脚本宿主请求 OCR，不要求也不允许在脚本子进程中单独加载 RapidOcrOnnx。
