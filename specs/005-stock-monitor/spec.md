# Feature Specification: 独立看盘应用与股票字体颜色识别

**Feature Branch**: `[005-stock-monitor]`

**Created**: 2026-11-22

**Status**: Draft

**Input**: 用户要求“在目前项目基础上，增加一个看盘应用，单独开一个进程”，依据 `docs/rpa看盘设计.md`。

## User Scenarios & Testing

### User Story 1 - 独立启动看盘应用并获取行情截图 (Priority: P1)

用户可以在 WinAuto 之外单独启动看盘应用，并在不关闭或改变 RPA 工作流的情况下使用它。用户可以载入一张截图，或主动选择正在运行的同花顺 9.x 窗口进行截图分析。

**Why this priority**: 独立进程是本需求的核心边界；可控地提供图像输入是识别功能的起点。

**Independent Test**: 在同一台电脑上同时运行 RPA 与看盘应用。分别载入测试截图、捕获同花顺窗口；确认看盘应用正常运行，RPA 的执行状态和未保存工作流不变。

**Acceptance Scenarios**:

1. **Given** 看盘应用已安装，**When** 用户单独启动它，**Then** 系统启动独立的可执行程序和进程，不要求先启动 RPA，也不把看盘界面嵌入 RPA 主窗口。
2. **Given** 用户选择一张有效截图，**When** 用户请求分析，**Then** 系统使用该图像进行识别，并保留截图坐标与识别结果之间的对应关系。
3. **Given** 同花顺 9.x 窗口正在运行，**When** 用户选择该窗口并发起一次截图分析，**Then** 系统只读取目标窗口图像，不发送鼠标键盘输入、不改变窗口内容。
4. **Given** RPA 正在编辑或执行工作流，**When** 看盘应用启动、分析图像或关闭，**Then** RPA 的工作流、执行授权和运行状态均不被看盘应用重置或替换。

### User Story 2 - 识别股票行并分类字体颜色 (Priority: P1)

用户可以查看截图中识别出的股票代码、名称、文字区域和置信度，以及由股票名称字体颜色生成的连板等级或关注属性。股票代码颜色用于交叉核验；颜色冲突、识别失败或置信度不足时，系统显示待确认或未知，不猜测分类。

**Why this priority**: 颜色分类是设计文档明确的首期业务能力，也是未来股票监控能力的数据基础。

**Independent Test**: 使用含有五种目标字体颜色及股票代码、名称的人工标注截图，检查 OCR 文字框与股票行关联、颜色结果和分类标签；另外覆盖低置信度、颜色冲突、灰色文字和涨幅红绿文字。

**Acceptance Scenarios**:

1. **Given** 截图中存在可识别的股票代码和名称，**When** OCR 返回文字、坐标和识别置信度，**Then** 系统按文字框位置将代码、名称关联到对应行，并以股票名称区域作为主要颜色采样区。
2. **Given** 名称颜色可靠地识别为红、橙或紫红，**When** 系统分类该行，**Then** 分别产生“三板及以上”“一板”“二板”连板标签。
3. **Given** 名称颜色可靠地识别为白或黄，**When** 系统分类该行，**Then** 分别产生“自选股”或“非关注股票”关注属性；不得据此推断连板等级。
4. **Given** 名称颜色未知或低于置信度阈值，**When** 系统完成分类，**Then** 连板等级和关注属性保持未知。
5. **Given** 股票名称与代码颜色均有可靠结果但彼此冲突，**When** 系统组合行级结果，**Then** 标记 `COLOR_CONFLICT` 并待用户确认，不选择其中一个颜色覆盖另一个。
6. **Given** 价格或涨幅文字呈红色或绿色，**When** 系统进行股票分类，**Then** 这些区域不作为字体业务分类依据。

### User Story 3 - 调试、校准和复核识别结果 (Priority: P1)

用户可以检查颜色分类的依据，调整颜色阈值并对当前截图重新分析，复核不可靠结果，并将识别结果显式导出为 JSON。阈值和布局配置可独立保存，不需修改程序代码。

**Why this priority**: 设计文档要求通过同花顺真实截图校准颜色；可解释的调试能力是避免误分类的必要手段。

**Independent Test**: 加载标注截图，对名称文字框进行颜色采样，检查 RGB/HSV、主色占比、颜色置信度、OCR 置信度和分类标签；调整阈值后立即重算并保存设置，导出结果后验证内容和坐标。

**Acceptance Scenarios**:

1. **Given** 用户打开一次分析结果，**When** 用户检查某个股票名称区域，**Then** 系统显示该区域、主要 RGB/HSV 值、有效前景像素和主色占比、颜色置信度、OCR 置信度及分类结果。
2. **Given** 用户调整有效颜色阈值，**When** 配置应用，**Then** 当前图像的颜色结果可重新计算，之后启动应用仍使用保存的配置。
3. **Given** 用户选择一个识别区域作为样本，**When** 用户显式导出，**Then** 系统导出包含图像/文字区域关联、颜色分析和标签的 JSON；未执行导出时不自动生成识别结果文件。
4. **Given** 用户发现颜色结果低置信度或代码/名称冲突，**When** 用户复核结果，**Then** 系统保留原始算法结果并清晰标示待确认状态，不将人工确认伪装成算法置信度。
5. **Given** 用户导入无效配置或调整到非法阈值，**When** 系统验证配置，**Then** 系统给出具体字段错误并保留上一次有效配置。

### User Story 4 - 保存并查看股票分类历史快照 (Priority: P2)

用户可以将一次识别得到的股票分类显式保存为带时间和来源页面的历史快照，之后查看保存过的分类记录。快照表达的是行情界面当时显示的分类，不宣称股票已实际涨停或完成连板晋级。

**Why this priority**: 设计文档要求保留历史分类快照，以便后续扩展梯队变化分析；历史记录不是完成首期识别闭环的前提，因此优先级低于识别与校准。

**Independent Test**: 对同一测试截图执行两次识别并保存，确认两次记录分别带有采集时间、股票代码、分类、置信度和来源；关闭并重启应用后仍可查询。

**Acceptance Scenarios**:

1. **Given** 一次分析存在可保存结果，**When** 用户确认保存快照，**Then** 系统持久化股票代码、字体颜色、连板等级、关注属性、颜色置信度、来源页面和采集时间。
2. **Given** 两次分析得到同一股票的不同分类，**When** 两次结果均被保存，**Then** 系统保留各自的历史记录，不以新值覆盖旧快照。
3. **Given** 数据库不可读写或存储空间不足，**When** 用户保存快照，**Then** 系统报告保存失败，界面中当前分析结果仍可查看，且不显示为已保存。

## Scope Boundaries

本规格涵盖一个独立运行的 Windows 看盘应用首期：截图输入、OCR 股票行关联、字体颜色分析、分类展示、阈值调试、JSON 导出和可选的 SQLite 历史快照。

以下后续能力不属于本期交付：自动统计/预测连板晋级、涨停真实性判断、热点板块与板块成分股分析、自动交易或下单、行情数据网络服务、无人值守定时监控，以及与 RPA 之间的自动工作流或 IPC 联动。字体颜色只能表示同花顺界面显示的分类，不能单独证明涨停、连板晋级或板块归属。

## Edge Cases

- OCR 未检测到文本、文字框坐标越界/重叠、股票代码或名称缺失，或一行中出现多个可能的代码/名称。
- 股票代码、名称被 OCR 误识别，或 OCR 返回置信度低于配置阈值。
- 代码与名称所在行的颜色冲突；名称和代码颜色一致但颜色本身置信度低。
- 文字框混入背景、选中高亮、抗锯齿、网格线或相邻列像素；区域太小或有效前景像素不足。
- 名称颜色处于红/橙、黄/白、紫红/红的阈值边界，或混合色没有明确主色。
- 涨幅/价格列的红绿颜色与名称分类颜色相同；系统必须排除这些列。
- 同花顺窗口不存在、最小化、被遮挡、尺寸变化或截图失败；不得将错误图像作为有效分析结果。
- 无效/不兼容的 OCR 模型、字典、颜色配置、表格布局、SQLite 数据库或 JSON 导出路径。
- OCR/颜色计算耗时较长、应用关闭或用户取消分析；界面不可假报成功或一直保留“分析中”状态。
- RPA 与看盘应用同时运行；两者的窗口、配置、数据库和运行状态不得意外互相覆盖。
- 同一股票被多次分析或其界面分类随时间改变；历史快照须保留，不把界面标签解释为经外部行情验证的事实。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供独立的看盘可执行程序和进程；它 MUST 可与 WinAuto UI/CLI 同时运行，且不得依赖 RPA 进程的启动、生命周期或未保存工作流状态。
- **FR-002**: 看盘应用 MUST 提供用户主动触发的截图输入，至少支持载入截图文件和捕获用户选择的目标窗口；不得在首期默认进行无人值守定时截图。
- **FR-003**: 系统 MUST 使用本地 OCR 处理图像，并取得每个文字区域的识别文本、边界框及 OCR 置信度；不得仅凭拼接文本推算文字框位置。
- **FR-004**: 系统 MUST 将 OCR 文字区域按几何位置组合成股票行候选，识别股票代码和名称；未能可靠关联的字段或行 MUST 标记为未知/待确认。
- **FR-005**: 系统 MUST 将原始截图和 OCR 原始文字框关联用于颜色采样；不得从重新绘制、灰度化或经 OCR 修改的图片推断原始字体颜色。
- **FR-006**: 颜色分析 MUST 提取文字框内有效前景像素，使用 HSV 为主、RGB 为辅识别红、白、橙、黄、紫红五类颜色，并统计主色占比和识别置信度。
- **FR-007**: 颜色类别 MUST 支持由独立配置文件调整阈值；非法配置不得覆盖最后一份有效配置。
- **FR-008**: 系统 MUST 支持批量文字框颜色分析；小区域、有效采样不足、颜色混合或置信度不足的结果 MUST 返回 `UNKNOWN`，不得强行归类。
- **FR-009**: 系统 MUST 以股票名称颜色作为主要分类依据，以股票代码颜色作为辅助交叉验证；只有明确冲突时 MUST 标记 `COLOR_CONFLICT`，不得静默选择一方。
- **FR-010**: 系统 MUST 将红色映射为 `BOARD_3_PLUS`，橙色映射为 `BOARD_1`，紫红色映射为 `BOARD_2`，白色映射为 `WATCHLIST`，黄色映射为 `NOT_FOLLOWED`。
- **FR-011**: 连板等级与关注属性 MUST 是独立数据维度；白色和黄色结果不得推导连板等级，红色/橙色/紫红色结果不得推导自选股或非关注属性。
- **FR-012**: 股票行颜色分析 MUST 不使用最新价、涨幅、成交额等数值列作为分类输入。
- **FR-013**: 调试界面 MUST 展示原图和选中/识别文字框，以及 RGB/HSV、有效前景像素数、主色占比、颜色置信度、OCR 置信度、颜色类别和股票标签。
- **FR-014**: 用户 MUST 能调整有效颜色阈值并对当前分析结果重新计算；颜色设置和表格布局设置 MUST 与 RPA 工作流配置分离保存。
- **FR-015**: 用户 MUST 能显式导出一次分析的 JSON 结果；导出 MUST 包括股票行/代码/名称、文字框坐标、字体颜色、分类标签、置信度、来源页面和采集时间；未经用户操作不得自动导出识别结果或截图。
- **FR-016**: 用户 MUST 能显式保存分类历史快照；SQLite 快照 MUST 保留各次采集记录，而不是只覆盖当前股票状态。
- **FR-017**: 系统 MUST 明确区分截图、OCR、颜色分类、行关联和数据库保存失败；失败不得显示为成功、无匹配或未知分类等误导性结果。
- **FR-018**: 截图获取、OCR 推理和批量颜色分析 MUST 不阻塞 Qt UI 主线程；取消或关闭时 MUST 清理进行中的任务并呈现明确状态。
- **FR-019**: 系统 MUST 保持 WinAuto 原有 RPA 执行、流程编辑、OCR 配置及工作流格式不变；看盘应用不得向同花顺窗口发送输入或执行交易操作。
- **FR-020**: 系统 MUST 将 `board_stage` 与 `follow_status` 分别存储，并保留未知值；分类数据 MUST 能追溯到采集时间和来源页面。
- **FR-021**: 系统 MUST 默认将识别和分类视为本地处理；除用户显式选择的 JSON 导出外，不得将截图或识别文本发送到外部网络服务。

### Key Entities

- **字体颜色类别**：Unknown、Red、White、Orange、Yellow、Magenta。
- **股票分类**：独立的连板等级、关注属性、标签、颜色识别状态和颜色置信度。
- **颜色分析结果**：主色、代表色、文字区域、有效前景像素数、主色像素数/比例、置信度和有效状态。
- **OCR 文字区域**：识别文本、截图坐标边界框和 OCR 置信度。
- **股票行候选**：行区域、代码/名称及其文字框、可选其他字段、名称/代码颜色结果和冲突状态。
- **颜色规则配置**：规则版本、启用状态、采样/回退模式、前景过滤条件、颜色阈值和最低置信度。
- **分类历史快照**：股票代码、字体颜色、连板等级、关注属性、颜色置信度、来源页面和采集时间。
- **一次分析**：截图来源、采集时间、OCR/颜色/行关联结果和本次处理状态；截图本身不因分析而自动保存到历史记录。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 看盘应用可作为独立进程启动，并可与 RPA 同时工作；并行验收中 RPA 工作流丢失、被修改或被看盘应用执行输入的次数为零。
- **SC-002**: 在经人工标注且覆盖五种颜色的真实同花顺截图测试集上，五类字体颜色总体分类准确率达到或超过 98%。
- **SC-003**: 在同一测试集上，股票名称颜色识别准确率达到或超过 98%，股票代码与名称行关联正确率达到或超过 99%。
- **SC-004**: 低于配置置信度阈值的颜色被错误分类为已知类别的次数为零；代码/名称颜色冲突被静默合并的次数为零。
- **SC-005**: 股票价格和涨幅列颜色导致的连板标签误分类次数为零。
- **SC-006**: 在目标测试机器上，单个文字框颜色分析耗时不超过 5 ms；图像分析期间 UI 主线程阻塞次数为零。
- **SC-007**: 调整阈值后，当前截图可在无需重启应用的情况下重新分类；重启后已保存的有效阈值仍生效。
- **SC-008**: 用户显式保存的分类快照在应用重启后均可查询，重复采集记录未被覆盖。
- **SC-009**: 截图、OCR、颜色分析、导出和数据库失败测试中，失败被报告为成功的次数为零。

## Assumptions

- 首期交付以 `docs/rpa看盘设计.md` 提出的独立 `FontColorDebugDemo` 为范围：完成同花顺 9.x 股票名称颜色分类和调试校准后，再考虑龙头、连板梯队、热点板块等业务。
- 目标操作系统为 Windows；使用仓库现有 Visual Studio 2019、Win32 和 Qt 5.15.x 工程环境。程序名和安装器细节由实现计划确定。
- 设计文档指定 RapidOCR 需返回文字框与置信度；仓库当前使用的 RapidOcrOnnx CLIB 适配只返回拼接文本，无法满足该数据契约。实现前必须选用/接入具备文字框与置信度的本地 OCR 接口；不得用猜测坐标替代。
- 当前 OCR 模型/依赖在目标 Win32 构建环境中可部署；缺失或不兼容时应用须明确诊断，不能悄悄退化为没有框坐标的识别。
- 首期允许用户主动选择图像文件或发起目标窗口截图；自动周期采集、股票交易日历、外部行情源和实时行情确认不在范围内。
- 五种颜色与业务标签采用设计文档确认的映射；`BOARD_3_PLUS` 等仅表示同花顺界面颜色规则产生的视觉分类，不是对交易结果的权威判断。
- 名称颜色是主要分类来源，代码颜色可缺失；名称和代码明确冲突时优先保留冲突状态，不推断真实分类。
- SQLite 保留用户显式保存的分类历史快照；首期不定义自动清理期限、跨设备同步或远端数据库。
- 识别准确率以人工标注的真实截图样本统计；纯色合成图片只用于算法单元测试，不能作为唯一验收依据。
- 看盘应用可复用仓库中与平台无关的算法/数据代码，但必须作为独立进程和独立用户界面交付，不新增与 RPA 执行器的自动 IPC 联动。
