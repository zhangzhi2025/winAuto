# Feature Specification: 看盘区域配置与定时识别

**Feature Branch**: `[006-region-based-stock-monitoring]`

**Created**: 2026-11-23

**Status**: Draft

**Input**: 用户要求在现有独立看盘应用中支持选定窗口内多个识别区域、为区域设置截取间隔、将配置保存为 JSON 并在以后重新打开，以及配置每日运行时段和表格行字段类型；参考 `docs/选定区域识别.md`。

## User Scenarios & Testing

### User Story 1 - 选择窗口并配置多个采集区域 (Priority: P1)

用户选择一个正在运行的目标窗口，在其客户区内框选一个或多个区域，为各区域命名并设置独立采集间隔。用户可以调整、启用/停用或删除区域；窗口和区域均可在开始采集前预览确认。

**Why this priority**: 区域化是避免 OCR 猜测整个应用页面结构的基础；一个窗口内多区域配置是本需求的核心。

**Independent Test**: 选择测试窗口并建立两个不重叠区域，检查预览截图与区域边界；移动窗口但保持客户区尺寸不变时验证区域仍有效，改变客户区尺寸后验证配置被判定为不匹配并停止使用，直至用户重新校准并保存。

**Acceptance Scenarios**:

1. **Given** 目标窗口可见且未最小化，**When** 用户框选客户区的一部分，**Then** 系统创建该窗口客户区内的区域配置，并显示名称、边界及截图预览。
2. **Given** 一个窗口已有多个区域，**When** 用户分别设置各区域的采集间隔、启用状态或边界，**Then** 每项设置只影响对应区域，且用户可在开始前检查最终配置。
3. **Given** 目标窗口移动但客户区物理像素尺寸未改变，**When** 系统使用已保存区域，**Then** 区域仍按客户区坐标工作；若客户区宽度或高度与配置记录不完全相同，系统将配置标记为尺寸不匹配、禁止该配置截图/识别，并要求用户重新校准和保存，不按比例缩放或静默截取。
4. **Given** 窗口已关闭、最小化、客户区为空或区域超出客户区，**When** 用户选择或确认区域，**Then** 系统说明原因并阻止保存为可运行配置。

### User Story 2 - 定义表格行和字段类型 (Priority: P1)

用户可以将区域设置为普通文字识别或表格识别。表格模式允许用户为一行定义多个字段、字段名称、横向边界及文字类型；系统按配置的行高/行距在区域中重复识别该行模板。类型示例包括文字、整数、小数、百分比、价格和日期/时间。

**Why this priority**: 用户需要把 OCR 文字从整块结果转成稳定、可校验的行字段，且字段含义和格式不能由 OCR 自行猜测。

**Independent Test**: 在固定测试截图上配置一行含文字、数字和百分比的表格模板，确认每个结果字段关联到配置列，保留原始 OCR 文本并产生正确类型值或明确的格式错误。

**Acceptance Scenarios**:

1. **Given** 用户为区域开启表格模式，**When** 用户添加或编辑一行模板字段，**Then** 可为各字段设置稳定名称、相对区域的列边界和数据类型，并可预览字段覆盖范围。
2. **Given** 表格模板定义了首行位置及行高/行距，**When** 系统识别区域内多行内容，**Then** 按该模板逐行输出字段，不把相邻列或相邻行的文字静默合并。
3. **Given** 某字段的 OCR 原文符合其类型，**When** 系统转换字段值，**Then** 同时保留原文与类型化值；百分比保留其百分比语义，不与普通小数混淆。
4. **Given** 字段原文无法转换为设置的类型或 OCR 未识别到字段，**When** 系统生成结果，**Then** 保留可用原文并将该字段标记为解析失败/缺失，不填入猜测值，也不丢弃同行其他字段。
5. **Given** 用户未配置表格模板或选择普通文字模式，**When** 系统处理区域，**Then** 返回该区域内 OCR 文字、边界与置信度，不自行推断列、行或业务类型。

### User Story 3 - 保存、重新打开和校验 JSON 配置 (Priority: P1)

用户可以将一个窗口及其多个区域、字段模板、采集间隔和每日运行时段保存为独立 JSON 配置文件；之后可打开该文件继续编辑或运行。配置加载不自动开始采集，也不要求持久化进程内窗口句柄。

**Why this priority**: 区域框选和表格模板属于一次性配置；可复用和可诊断的保存/加载是实际重复使用的前提。

**Independent Test**: 保存多区域配置、关闭应用、重新打开 JSON 并重新选择目标窗口；对照区域、类型、间隔和时间设置，确认一致；再分别载入格式错误、未知版本和越界配置。

**Acceptance Scenarios**:

1. **Given** 配置完整且通过校验，**When** 用户保存为 JSON 并重新打开，**Then** 系统还原所有区域、字段模板、采集间隔和每日运行时段。
2. **Given** 配置已打开但尚未保存，**When** 用户尝试关闭、打开另一文件或加载默认配置，**Then** 系统提醒未保存修改，并遵循用户选择。
3. **Given** 用户打开已有配置，**When** 配置文件有效，**Then** 系统恢复配置但保持停止状态，并要求用户重新选择当前有效的目标窗口；只有当前窗口客户区物理像素尺寸与配置中记录的尺寸完全一致时，该配置才可用于采集。
4. **Given** JSON 无法解析、缺少必需字段、使用不支持的主版本或包含非法区域/时间/字段类型，**When** 用户加载，**Then** 系统显示具体字段路径和原因，保留当前有效配置，不部分覆盖。
5. **Given** 用户保存到不可写路径或磁盘操作失败，**When** 保存失败，**Then** 系统明确报告失败，保留当前内存配置和原配置文件，不显示为已保存。

### User Story 4 - 在每日运行时段定时采集并停止 (Priority: P1)

当用户已选择目标窗口、加载有效配置并确认区域后，可以开始和结束采集。每日开始/结束时间对配置中的所有区域生效，各区域按自己的采集间隔运行；到达每日结束时间后系统自动暂停，并允许用户手动停止或重新开始。

**Why this priority**: 区域模板的实际用途是按用户控制的频率重复采集；开始/结束控制和每日时间边界必须明确且安全。

**Independent Test**: 使用可注入时钟和截图/OCR fake，为两个区域设置不同间隔与有限每日时段；验证开始、时段外不采集、到达结束时间停止派发、手动停止后不产生新任务、慢任务不会无限排队。

**Acceptance Scenarios**:

1. **Given** 已选择有效窗口且配置完整，当前时间位于每日运行时段内，**When** 用户点击“开始”，**Then** 系统启动各启用区域的采集调度并显示运行状态和下次采集信息。
2. **Given** 当前时间早于每日开始时间，**When** 用户点击“开始”，**Then** 会话进入已启动/等待时段状态，在每日开始时间到达前不截图；到达时段后开始采集。
3. **Given** 采集正在进行，**When** 用户点击“结束”，**Then** 系统停止提交新截图/OCR 任务、清空尚未开始的排队任务，并明确显示当前已开始任务的完成或取消状态。
4. **Given** 当前时间到达每日结束时间，**When** 调度器处理时段边界，**Then** 不再为该日派发任务并显示已结束；次日不自动运行，除非用户再次点击开始。
5. **Given** 某区域的上次 OCR 尚未完成，**When** 该区域的下一采集周期到达，**Then** 跳过本周期或合并为一次待采集，不重复并发处理同一区域、不无限积压；其他区域仍可按调度继续。
6. **Given** 某个区域截图或 OCR 失败，**When** 系统报告该区域结果，**Then** 明确记录区域、时间和失败原因，保留其他区域独立运行；目标窗口失效时停止整个会话并要求重新选择窗口。
7. **Given** 用户在采集运行期间编辑配置或切换目标窗口，**When** 操作会改变当前任务含义，**Then** 系统要求先停止，避免在同一会话中混用新旧配置。
8. **Given** 当前时间已到当日结束时间之后，**When** 用户再次明确点击“开始”，**Then** 系统进入等待下一次每日开始时间的状态；没有这次明确操作时，次日不得自动采集。

### User Story 5 - 检查区域截图和结构化识别结果 (Priority: P1)

用户可以查看每个区域最近一次截图、识别状态和结果；表格模式下按行展示字段原文、类型化值、OCR 置信度及字段解析状态。失败、低置信度和缺失项必须可见，不得用默认值掩盖。

**Why this priority**: 定时采集的结果需要可检查，用户才能发现区域校准、OCR 或字段格式问题。

**Independent Test**: 对包含正常行、缺列行和类型不匹配值的测试图执行单次区域识别；验证截图、原始文字、字段值、置信度和失败状态均可区分。

**Acceptance Scenarios**:

1. **Given** 某区域完成一次识别，**When** 用户查看该区域，**Then** 系统显示采集时间、区域截图、OCR 文字及框坐标/置信度，并按配置展示字段结果。
2. **Given** 某字段解析失败、缺失或低置信度，**When** 用户查看行结果，**Then** 该字段单独标注状态和原始证据，不阻止其他有效字段显示。
3. **Given** 某区域截图或 OCR 失败，**When** 该次采集结果展示，**Then** 显示失败而不是成功的空表格或上一周期内容；上一周期结果若仍显示，必须显著标注其采集时间和过期状态。
4. **Given** 用户显式执行单次截图/识别测试，**When** 完成处理，**Then** 不改变定时运行状态，不发送鼠标键盘输入，也不自动保存截图或结果到 JSON/数据库。

## Scope Boundaries

本规格扩展 `stock-monitor` 独立应用，提供单窗口多区域配置、区域截图、表格字段模板、JSON 配置读写、每日采集时段和按区域周期识别。继续复用已有 RapidOcrOnnx 文字框识别、字体颜色分析、股票行组装和分类能力；配置了相应字段或分析选项时才执行对应业务分析。

以下不属于本期：自动理解同花顺页面布局、自动发现列/行语义、跨多个目标窗口的单一配置、股票行情联网校验、交易或 RPA 输入、配置云同步、自动上传截图/结果、SQLite 历史数据平台、图像变化检测优化、跨午夜运行窗口和基于 OCR 文本自动改写配置。

## Edge Cases

- 目标窗口标题重复、句柄在应用重启后失效、窗口关闭/最小化、客户区尺寸改变、DPI 或显示器改变、窗口部分移出桌面或被其他窗口遮挡。
- 区域边界太小、为空、重叠、超出客户区，或窗口客户区尺寸改变后与配置记录不匹配。
- 多区域间隔不同、短间隔 OCR 耗时超过间隔、区域连续失败、用户暂停/停止时仍有截图或 OCR 在途。
- 应用在每日开始前启动、运行中系统时间跳变/休眠唤醒、到达结束时间时任务仍在处理，或用户跨越午夜保持应用运行。
- 表格头部、空行、合并单元格、行高变化、滚动导致行内容变化、不同字段边界重叠或文字跨列。
- OCR 返回空文本、多候选文字框、低置信度、越界框或字符置信度无效。
- 数字带千分位、正负号、小数点、百分号、货币符号或本地化格式；配置类型与显示格式不一致。
- JSON 文件损坏、版本不支持、写入中断、路径只读或文件被外部进程修改。
- 采集进行时关闭应用、切换窗口、编辑配置或重新加载配置；不得残留显示为运行中的任务或把旧任务结果写入新配置。
- 同一周期多个区域同时到期；调度应有界并维持区域之间的隔离，不能因一个慢区域无限阻塞所有区域。
- 截图基于屏幕可见内容；遮挡窗口可能进入截图，最小化或不可捕获状态必须明确报告，不能伪称为目标窗口完整画面。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 在现有独立 `stock-monitor` 应用中提供区域配置和识别工作台；不得依赖 WinAuto 工作流、脚本或桌面输入执行进程。
- **FR-002**: 每份配置 MUST 绑定一个目标窗口身份提示并支持该窗口内多个采集区域；配置文件 MUST NOT 持久化可复用的原生窗口句柄，加载后须由用户重新选择当前有效窗口。
- **FR-003**: 用户 MUST 能在选定窗口客户区中框选、预览、新增、编辑、启用/停用和删除多个区域，并为每个区域设置名称和以毫秒计的大于零采集间隔。
- **FR-004**: 配置 MUST 持久化创建时窗口客户区的宽度和高度（物理像素）、区域相对于该客户区左上角的坐标及必要的 DPI/配置版本信息。运行时客户区宽度和高度 MUST 与记录值完全一致，否则整个配置 MUST 标记为尺寸不匹配并禁止截图、OCR 和定时采集，直至用户重新校准并保存；系统 MUST NOT 按比例缩放、裁切或以其他方式自动适配区域坐标。
- **FR-005**: 系统 MUST 支持一键对选定区域执行单次截图及可选 OCR 测试；单次测试不得启动、停止或修改定时调度状态。
- **FR-006**: 每个区域 MUST 支持普通 OCR 模式；结果保留 OCR 提供的原文、框坐标和置信度，不得只保留经字段转换后的值。
- **FR-007**: 用户 MUST 能为区域选择表格模式，并为一行模板定义一个或多个字段；每个字段包含稳定字段名、区域相对的横向范围和数据类型。
- **FR-008**: 表格模板 MUST 支持配置首个数据行位置及行高/行距，按模板重复识别区域内数据行；未配置模板时 MUST NOT 自动推断字段列、业务类型或表格语义。
- **FR-009**: 字段类型 MUST 至少支持文本、整数、十进制数和百分比；实现计划可扩展价格、日期/时间等类型。字段结果 MUST 保留原始 OCR 文本及独立的类型化值/解析状态，格式错误或字段缺失不得填入推测值。
- **FR-010**: 字段配置 MUST 能指定是否启用字段文字颜色分析；启用时使用原始截图像素及对应文字框，沿用现有颜色分类结果和未知状态，不得从 OCR 预处理图像推断颜色。
- **FR-011**: 用户 MUST 能设置每日开始时间和结束时间，作为该配置内所有启用区域的共同运行窗口；使用本机当地时间，开始时间须早于结束时间，初版不支持跨午夜时段。
- **FR-012**: 用户 MUST 能显式开始和结束采集；开始前必须验证目标窗口、配置和区域边界。未到每日开始时间时可进入等待状态；结束时间到达后停止派发当日新任务并结束会话。结束后只有用户再次明确点击“开始”才可等待下一次每日开始时间，不得自行延续到次日。
- **FR-013**: 各启用区域 MUST 按其配置的间隔独立调度；同一区域最多一个在途 OCR 任务，队列 MUST 有界。跳过/合并周期时须可观察，不得无限积压或不透明地重复处理。
- **FR-014**: 用户手动结束 MUST 阻止新任务派发并取消尚未开始的排队任务；对已开始任务 MUST 明确完成、取消或失败状态。目标窗口失效时 MUST 停止整次会话并报告原因。
- **FR-015**: 单一区域截图或 OCR 失败 MUST 带区域标识、采集时间和原因呈现，且不得覆盖为成功空结果；其他区域在目标窗口仍有效时可以继续采集。
- **FR-016**: 系统 MUST 提供版本化 JSON 配置的显式保存、另存为和打开/加载能力，内容覆盖窗口身份提示、区域坐标与参考尺寸、启用状态、采集间隔、字段模板和每日时段。
- **FR-017**: JSON 配置 MUST 完整解析并校验后原子替换当前配置；错误路径、未知不兼容版本、无效范围或非法类型须产生明确诊断并保留上一次有效配置。
- **FR-018**: 配置加载 MUST 保持采集停止状态，不得因自动加载配置而自动捕获窗口；未保存修改在替换/关闭前 MUST 提醒用户。
- **FR-019**: 采集界面 MUST 能查看各区域最近一次截图、采集时间、处理状态和 OCR 结果；表格字段展示原文、类型化值、置信度及缺失/格式错误状态。
- **FR-020**: 截图、OCR、字段转换、JSON 加载/保存、取消和窗口不可用 MUST 使用可区分状态；任何失败均不得伪装成成功、无文字或未知字段值。
- **FR-021**: 定时采集与 OCR MUST 不阻塞 Qt 主线程；关闭应用、停止会话或换用新配置时，过期任务结果不得覆盖新会话状态。
- **FR-022**: 采集只读目标窗口，不得发送鼠标、键盘或交易指令；识别结果和截图默认只在内存中保留，不得未经用户显式操作自动写入 JSON、数据库或外部网络。
- **FR-023**: 系统 MUST 明确告知采集基于目标窗口在桌面上的可见客户区像素；最小化、离屏、捕获失败等情况须拒绝或报错，被其他窗口遮挡时不得声称获得了完整未遮挡内容。

### Key Entities

- **RegionCaptureConfig**：版本、目标窗口身份提示、参考客户区尺寸/DPI、每日开始/结束时刻及多个区域配置。
- **CaptureRegion**：稳定 ID、名称、以客户区左上角为原点的像素矩形、启用状态、采集间隔和识别模式；只能用于匹配配置记录宽高的客户区。
- **TableTemplate**：区域内首个数据行位置、行高/行距和一个或多个字段定义。
- **FieldDefinition**：稳定字段名、相对列边界、值类型以及可选颜色分析设置。
- **TypedFieldValue**：原始 OCR 文本、可选类型化值、OCR 置信度、源文字框和转换状态。
- **RegionCaptureResult**：区域 ID、采集时间、截图尺寸、OCR 文字框、结构化行/字段及截图/OCR/解析状态；首期仅作为运行期结果。
- **CaptureSession**：当前目标窗口、已校验配置、运行/等待/停止状态、调度任务和取消状态；窗口句柄只在当前进程会话有效。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 保存并重新加载的配置中，区域、字段类型、采集间隔和每日时段与保存前完全一致；无效 JSON 导致当前有效配置被部分覆盖的次数为零。
- **SC-002**: 在客户区物理像素尺寸与配置完全相同的窗口上，区域坐标与保存值完全一致；宽度或高度任一不同时，配置截图/识别/定时任务派发数为零，并明确要求重新校准。
- **SC-003**: 在可注入时钟测试中，每个区域只在每日运行窗口内派发任务，开始/结束边界误差不超过一个调度周期，结束后新任务派发数为零。
- **SC-004**: 多区域长耗时测试中，每个区域的在途 OCR 数不超过 1，待处理任务有界，手动停止后新任务派发数为零。
- **SC-005**: 对类型测试集，文本、整数、小数和百分比结果均保留原文并正确生成类型化值；非法和缺失字段显示失败/缺失状态且不产生猜测值。
- **SC-006**: 截图/OCR/字段转换失败能够准确定位到区域和采集周期，错误误报为成功或空结果的次数为零。
- **SC-007**: 区域截图与 OCR 运行期间 UI 主线程无同步等待；用户停止/关闭后旧会话结果覆盖当前会话的次数为零。
- **SC-008**: 配置加载、单次测试、定时采集过程中目标窗口输入事件数为零；未经用户明确保存/导出的截图或结果落盘/发送次数为零。

## Assumptions

- 本功能扩展现有 Windows/Qt `stock-monitor`，复用已接入并通过样例推理验证的 RapidOcrOnnx 动态运行库、文字框适配器、字体颜色分析和股票行算法。
- 每份配置只绑定一个窗口，但可包含多个区域；需要监控另一个窗口时，用户停止当前会话并切换窗口或加载另一份配置。
- 保存区域时记录窗口客户区的物理像素宽高，并以客户区左上角为原点保存区域像素坐标；只有运行时客户区宽高完全匹配时才使用该配置。任何尺寸变化都要求用户重新校准并另行保存配置，窗口句柄只在运行期间使用。
- 每个区域使用固定表格模板；行高、起始位置或列布局发生变化时用户需要调整模板或重新校准，首期不使用机器学习自动发现布局。
- 每日时段使用操作系统本地时间，配置时间按 `[开始, 结束)` 解释，首期不支持跨午夜区间；到时段结束后需要用户重新点击开始才能开始下一交易日采集。
- 字段类型至少包含文本、整数、十进制数和百分比；更细的单位/本地化格式在 plan 阶段确定。无法解析时原文仍保留。
- 当前截图方式读取桌面上可见客户区像素，因此目标窗口应保持未最小化且尽可能不被遮挡；首期不承诺捕获被完全遮挡窗口的后台内容。
- 区域采集结果在内存中显示；该规格只要求持久化配置，不要求持久化逐周期截图、OCR 结果或历史行情。
- 未配置股票名称颜色分析的普通字段只执行 OCR 和类型转换；已配置股票业务分析的区域继续遵循既有未知/冲突规则。
